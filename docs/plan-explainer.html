Chess Board Architecture

These diagrams show the complex parts of the plan. Each section has a short explanation and one diagram.

1. The layers and the dependency rule

The app has four layers. A layer can use the layer below it. A layer cannot use a layer above it. The core is at the bottom. It has no DOM and no WebGL. The compiler stops a violation.

  • core/tsconfig.json has no "DOM" lib. Use of document or window fails the build.
  • An ESLint import rule stops core/ from importing any other folder.
  • Core tests run in Node. No browser is necessary.

2. One move, from pointer to pixels

This example moves a knight onto a square with a pawn. The view only converts pointer positions to square numbers. The interaction layer decides what the user wants. The core applies the one-piece-per-square rule and sends a diff.

3. Load order

The user sees the board before any JavaScript runs. The build writes the start position into the HTML with the same function the 2D view uses, so the view adopts those elements without a flash. The app JavaScript is one cached file. The 3D code is not in the first download. The app gets it during idle time, or when the user asks for 3D.

4. 3D picking: pointer to piece, pointer to square

In 3D, picking has two parts. To pick up a piece, the ray is tested against one simple, invisible cylinder for each piece. This matters at low camera angles: the head of a tall king can appear over the square behind it, and a plane test would select that square. To hover and drop, the ray is intersected with the flat board plane at height 0. This is one line of math per pointer event, shown below.

5. Render on demand

Many 3D apps draw 60 frames each second, all the time. That uses battery when nothing changes. Our 3D view draws a frame only when something changes. When the board is still, the GPU is idle.

  • One mesh for each piece, with shared geometry and materials: about 32 + 1 board = 33 draw calls. That is easy for a phone GPU, and add, remove, lift, and highlight stay simple.
  • Piece shapes are built in code from small profile arrays. No model files are downloaded.
  • The shadow map updates only when a piece moves.

6. A skin is data

A skin has no logic. It is a set of values that a view reads. To add a skin, add one folder and one registry entry. The app loads each skin as a separate small file, only when needed.
